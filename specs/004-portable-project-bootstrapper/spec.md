## User Scenarios & Testing *(mandatory)*

### User Story 1 - 100% Script-Free Spec Kit Skills & Ultra-Thin `.sh`/`.ps1` Terminal Seeders (Priority: P1)

Engineering teams and project maintainers starting a new repository—or adopting Spec Kit in an existing project—need a completely script-free set of Spec Kit workflow skills (`speckit-*` in `.agents/skills/`), an intelligent `/speckit-bootstrap` skill (`.agents/skills/speckit-bootstrap/SKILL.md`), and ultra-thin paired terminal seeder scripts (`bootstrap-speckit.sh` for Bash/macOS/Linux and `bootstrap-speckit.ps1` for PowerShell/Windows) that copy the `.specify/` and `.agents/` bundle into `<target-repo>` so the agent can immediately run `/speckit-bootstrap` and all downstream workflows without any runtime `.specify/scripts/` dependencies.

**Why this priority**: Phases 1–3 established a rich governance and multi-agent delivery suite inside this reference repository, but upstream skills still invoked `.specify/scripts/bash/*.sh` during execution, and adopting the suite across other repositories required manually copying dozens of files. Refactoring all skills to resolve `.specify/feature.json`, prerequisite artifacts, and the 4-tier template stack directly via native agent file operations—while providing ultra-thin `bootstrap-speckit.sh` and `bootstrap-speckit.ps1` file seeders plus `/speckit-bootstrap`—eliminates runtime shell-script dependencies and keeps terminal scripts trivial to maintain across Linux, macOS, and Windows.

**Independent Test**: Can be fully tested by verifying that zero `.agents/skills/speckit-*/SKILL.md` files reference `.specify/scripts/`, that `.specify/scripts/` is removed from the repository, and that running `./bootstrap-speckit.sh <target-dir>` or `pwsh ./bootstrap-speckit.ps1 <target-dir>` followed by `/speckit-bootstrap` initializes `.specify/` (core templates, Base Governance Preset, Orchestrator Extension, `extensions.yml`, and installation manifest), `.agents/skills/speckit-*/SKILL.md` (all 11 skills), `.agents/agents/speckit-{reasoner,executor}.md`, and `.gitignore` exclusions cleanly.

**Acceptance Scenarios**:

1. **Given** any Spec Kit skill in `.agents/skills/speckit-*/SKILL.md` (`specify`, `clarify`, `plan`, `tasks`, `checklist`, `analyze`, `implement`, `converge`, `constitution`, `orchestrate`, `bootstrap`), **When** an agent executes the skill, **Then** it resolves `.specify/feature.json`, feature artifact paths, and templates across the 4-tier resolution hierarchy (`.specify/templates/overrides/` → `.specify/presets/` → `.specify/extensions/` → `.specify/templates/`) directly through native agent file operations with zero invocations of `.specify/scripts/bash/*.sh`, and `.specify/scripts/` no longer exists in the repository.
2. **Given** a target project directory `<target-repo>`, **When** a developer runs `./bootstrap-speckit.sh <target-repo>` or `pwsh ./bootstrap-speckit.ps1 <target-repo>`, **Then** the seeder script validates `<target-repo>`, copies all managed `.specify/` (templates, presets, extensions, metadata) and `.agents/` (11 skills and 2 role-based agent definitions) files into `<target-repo>` without overwriting existing files (unless `--force` / `-Force` is passed) or ever touching protected user-state paths, and prints a concise handoff prompt to run `/speckit-bootstrap` in the agent.
3. **Given** a repository where `.specify/` and `.agents/` have been seeded (or when `/speckit-bootstrap <target-repo>` is invoked directly by an agent from the source toolkit repo), **When** `/speckit-bootstrap` runs, **Then** it verifies all managed files, merges `.agents/agents/*.local.md` into `.gitignore` and `speckit.orchestrate` into `.specify/extensions.yml`, writes `.specify/integrations/speckit-bootstrap.manifest.json`, and outputs a structured readiness report.

### User Story 2 - Agent-Driven Non-Destructive Upgrades & Override Preservation via `/speckit-bootstrap` (Priority: P2)

Maintainers of repositories that have already adopted Spec Kit need an intelligent, agent-driven upgrade and drift-inspection workflow (`/speckit-bootstrap --check` and `/speckit-bootstrap --upgrade [--source=<path>]`) that pulls newer versions of the base governance templates, workflow skills, and default role-based agent profiles while strictly preserving project-local overrides, ratified project constitutions and standards, and locally customized files.

**Why this priority**: Once a repository adopts Spec Kit, teams ratify their own `.specify/memory/{constitution,coding-standards,logging-standards}.md`, add project-specific template overrides in `.specify/templates/overrides/`, configure machine-local or stage-specific subagent profiles in `.agents/agents/`, or register additional hooks in `.specify/extensions.yml`. Delegating upgrade inspection, manifest comparison, and structured YAML/gitignore merging to the `/speckit-bootstrap` skill keeps the terminal scripts tiny while guaranteeing Constitutional Principle VI (*Verify Before Mutate/Destroy*).

**Independent Test**: Can be fully tested by seeding a target directory, creating ratified files in `.specify/memory/`, placing a custom template override in `.specify/templates/overrides/`, creating a `.local.md` agent override in `.agents/agents/`, and modifying a managed skill file, then running `/speckit-bootstrap` in `--check` and `--upgrade` modes and verifying that ratified governance files and local overrides remain untouched, unmodified managed files update cleanly, and locally modified managed files are flagged and skipped unless `--force` is explicitly provided.

**Acceptance Scenarios**:

1. **Given** a target repository inspected via `/speckit-bootstrap --check` (or `--dry-run`), **When** the skill executes, **Then** it compares the target repository against the source bundle and installation manifest and outputs a structured file-by-file plan (`CREATE`, `UPGRADE`, `PRESERVE_USER_STATE`, `SKIP_DRIFTED`, `REMOVE_OBSOLETE`, `UNCHANGED`) without modifying any files on disk.
2. **Given** a previously bootstrapped target repository containing ratified `.specify/memory/{constitution,coding-standards,logging-standards}.md`, active feature specs in `specs/`, and project-local template overrides in `.specify/templates/overrides/`, **When** `/speckit-bootstrap --upgrade` runs, **Then** all files in `.specify/memory/`, `specs/`, `.specify/feature.json`, `.specify/templates/overrides/`, and `.agents/agents/*.local.md` are 100% preserved, any unmodified legacy `.specify/scripts/` directory is cleanly removed, and unmodified preset templates and skills are updated to the latest version.
3. **Given** a previously bootstrapped target repository where a maintainer has manually edited a managed skill or agent file tracked in `.specify/integrations/speckit-bootstrap.manifest.json`, **When** `/speckit-bootstrap --upgrade` runs without `--force`, **Then** the skill detects the content drift against the recorded manifest digest, refuses to overwrite the locally modified file, logs a `WARN` diagnostic identifying the drifted file, and continues updating unmodified managed files.

### User Story 3 - First-Class Spec Kit Preset & Extension Packaging + Seamless Governance Initialization (Priority: P3)

Platform engineers and developers need the Phase 1–3 deliverables organized as first-class Spec Kit Preset (`.specify/presets/base-governance/`) and Extension (`.specify/extensions/speckit-orchestrator/`) packages in the repository, with `/speckit-bootstrap` able to directly chain into initial Constitutional + Standards Merge (`/speckit-constitution`) against the target repository.

**Why this priority**: Packaging Phase 1 templates as an official Spec Kit Preset registered in `.specify/presets/.registry` and Phase 3 orchestration as an official Spec Kit Extension registered in `.specify/extensions/.registry` aligns the repository with Spec Kit's native 4-tier priority resolution stack (`overrides` → `presets` → `extensions` → `core`). Having `/speckit-bootstrap` optionally invoke `/speckit-constitution` gives users a seamless onboarding experience from bare repository to ratified governance.

**Independent Test**: Can be fully tested by verifying `.specify/presets/base-governance/preset.yml` and `.specify/presets/.registry` alongside `.specify/extensions/speckit-orchestrator/extension.yml` and `.specify/extensions/.registry`, and verifying that `/speckit-bootstrap --init-governance` completes installation/verification and executes (or dispatches a subagent to execute) `/speckit-constitution` on the target repository.

**Acceptance Scenarios**:

1. **Given** the repository (or any bootstrapped target repository) with Phase 4 implemented, **When** any Spec Kit skill resolves `constitution-template`, `coding-standards-template`, or `logging-standards-template` across the 4-tier template stack, **Then** it discovers the active `base-governance` preset in `.specify/presets/base-governance/` (via `.specify/presets/.registry` and `preset.yml`) while allowing `.specify/templates/overrides/` to take Priority 1 precedence if a project creates a local override.
2. **Given** a target repository with an existing `.specify/extensions.yml` containing project-specific hook entries, **When** `/speckit-bootstrap` installs or upgrades the `speckit-orchestrator` extension hook, **Then** it merges the `speckit.orchestrate` entry under `hooks.after_specify` idempotently without removing or duplicating other hooks registered in `.specify/extensions.yml`.
3. **Given** a user running `/speckit-bootstrap --init-governance` (or confirming the governance initialization prompt at the end of `/speckit-bootstrap`), **When** bootstrap file verification completes, **Then** `/speckit-bootstrap` executes (or spawns a subagent to execute) `.agents/skills/speckit-constitution/SKILL.md` against the target repository to generate or merge `.specify/memory/{constitution,coding-standards,logging-standards}.md`.

### Edge Cases

- **Invalid, Missing, or Self-Targeting Destination Path**: If `<target-repo>` passed to `bootstrap-speckit.sh`, `bootstrap-speckit.ps1`, or `/speckit-bootstrap <target-repo>` is a regular file rather than a directory, is not writable, or points to the active source bundle root during an external copy operation, the tool MUST fail closed at the boundary before mutating any state and report a clear `WARN` rejection message.
- **Verify-Before-Mutate Pre-Flight Validation**: In compliance with Constitutional Principle II (*Fail Closed on Required State*) and Principle VI (*Verify Before Mutate/Destroy*), both the ultra-thin seeder scripts and `/speckit-bootstrap` MUST verify that all required source bundle files exist before writing to `<target-repo>`, and `/speckit-bootstrap` MUST classify all target file actions (`CREATE`, `UPGRADE`, `PRESERVE_USER_STATE`, `SKIP_DRIFTED`, `REMOVE_OBSOLETE`, `UNCHANGED`) before mutating target files.
- **Corrupted or Unparseable Existing `.specify/extensions.yml` or Manifests in Target Repo**: If a target repository already has a `.specify/extensions.yml`, `.specify/presets/.registry`, `.specify/extensions/.registry`, or `.specify/integration.json` that is malformed and cannot be safely parsed during `/speckit-bootstrap` merge/upgrade, the skill MUST NOT overwrite or silently truncate the file; it MUST abort the mutation, report the exact file and parse error, and leave the file untouched unless `--force` is explicitly supplied (in which case it backs up the malformed file to `<filename>.bak` before writing).
- **Legacy `.specify/scripts/` Cleanup**: When `/speckit-bootstrap` runs on a repository that previously had upstream `.specify/scripts/bash/*.sh` installed, it removes the obsolete `.specify/scripts/` directory and cleans `.specify/scripts/bash/*` entries from `.specify/integrations/speckit.manifest.json`.
- **Idempotent Re-Execution**: Running `bootstrap-speckit.sh <target-repo>`, `bootstrap-speckit.ps1 <target-repo>`, or `/speckit-bootstrap` twice in a row against the same target repository with the same source bundle version MUST result in zero file modifications (`0 created, 0 updated`) on the second run.
- **Strict Enforcement of Constitutional Principle III (No Automated Tests)**: Neither the bootstrapper nor the packaged preset/extension/skill bundle may generate or ship automated test suites (`tests/` directories, unit test scripts, or test tasks). All verification relies on static validation, `--check` dry-run inspection, and live verification of `/speckit-bootstrap` and the `.sh`/`.ps1` seeders.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: All Spec Kit skills in `.agents/skills/speckit-*/SKILL.md` (`speckit-specify`, `speckit-clarify`, `speckit-plan`, `speckit-tasks`, `speckit-checklist`, `speckit-analyze`, `speckit-implement`, `speckit-converge`, `speckit-constitution`, `speckit-orchestrate`) MUST be refactored to be 100% script-free, replacing all `.specify/scripts/bash/*.sh` invocations (`check-prerequisites.sh`, `resolve-template.sh`, `setup-plan.sh`, `setup-tasks.sh`) with direct, deterministic agent-native file and directory operations:
  - **Native Feature Path & Prerequisite Resolution**: Read `.specify/feature.json` (`feature_directory`, or `SPECIFY_FEATURE_DIRECTORY` if provided), resolve `FEATURE_DIR` (`<repo-root>/<feature_directory>`), and directly verify existence and non-emptiness of `spec.md`, `plan.md`, `tasks.md`, `research.md`, `data-model.md`, `quickstart.md`, `contracts/`, and `checklists/`.
  - **Native 4-Tier Template Resolution**: Resolve any `<template-name>` (`spec-template`, `plan-template`, `tasks-template`, `checklist-template`, `constitution-template`, `coding-standards-template`, `logging-standards-template`) directly across the Spec Kit priority stack:
    1. `.specify/templates/overrides/<template-name>.md`
    2. `.specify/presets/<preset-id>/templates/<template-name>.md` (ordered by priority in `.specify/presets/.registry` and honoring `preset.yml` strategies `replace`, `prepend`, `append`, `wrap`)
    3. `.specify/extensions/<ext-id>/templates/<template-name>.md` (ordered by priority in `.specify/extensions/.registry`)
    4. `.specify/templates/<template-name>.md` (core fallback).
  - **Removal of `.specify/scripts/`**: Delete `.specify/scripts/` from the repository, remove `.specify/scripts/bash/*` entries from `.specify/integrations/speckit.manifest.json`, and update `.specify/memory/constitution.md` (Pre-PR Verification) so no normative document or skill depends on `.specify/scripts/bash/`.
- **FR-002**: The repository MUST package the Phase 1 governance templates as a first-class Spec Kit Preset under `.specify/presets/base-governance/` registered in `.specify/presets/.registry`, containing:
  - A valid `.specify/presets/base-governance/preset.yml` manifest declaring `provides.templates` entries for `constitution-template`, `coding-standards-template`, and `logging-standards-template` (with `type: template` and `strategy: replace`).
  - The canonical `constitution-template.md`, `coding-standards-template.md`, and `logging-standards-template.md` files under `.specify/presets/base-governance/templates/` (kept synchronized with `.specify/templates/` so both preset and core fallback layers contain identical baseline templates).
- **FR-003**: The repository MUST package the Phase 3 orchestrator integration as a first-class Spec Kit Extension under `.specify/extensions/speckit-orchestrator/` registered in `.specify/extensions/.registry`, containing extension metadata (`extension.yml`) and the canonical `hooks.after_specify` hook definition (`speckit.orchestrate`) registered in `.specify/extensions.yml`.
- **FR-004**: The repository MUST provide ultra-thin, paired cross-platform terminal seeder scripts at the repository root—`bootstrap-speckit.sh` (Bash/POSIX) and `bootstrap-speckit.ps1` (PowerShell)—whose sole responsibility is seeding `.specify/` and `.agents/` files into a `<target-repo>` directory from the command line:
  - Accept `<target-repo>` and optional `--force` / `-Force` and `--help` / `-Help` flags.
  - Validate that all required source bundle files exist and that `<target-repo>` is a valid, writable directory (creating it if it does not yet exist) and is not the source repository itself.
  - Copy managed files under `.specify/` (`templates/*.md`, `presets/**`, `extensions/**`, `extensions.yml`, `init-options.json`, `integration.json`, `integrations/*.manifest.json`, `workflows/**`, `.specify/.gitignore`) and `.agents/` (`skills/speckit-*/SKILL.md` for all 11 skills and `agents/speckit-{reasoner,executor}.md`) into `<target-repo>`.
  - Skip any managed file that already exists in `<target-repo>` unless `--force` / `-Force` is passed, and **never** overwrite protected user-state files even when `--force` / `-Force` is passed.
  - Append `.agents/agents/*.local.md` to `<target-repo>/.gitignore` if not already present, and output a concise summary and next-step instruction to run `/speckit-bootstrap` (or `/speckit-constitution`) in the AI agent.
- **FR-005**: The repository MUST provide a dedicated bootstrapper skill at `.agents/skills/speckit-bootstrap/SKILL.md` (invokable as `/speckit-bootstrap`) that performs all rich verification, configuration merging, upgrade, and governance-initialization logic using native agent file operations:
  - **Self-Check / Post-Seed Verification Mode (default when invoked in a seeded repo without `<target-repo>`)**: Verifies all managed `.specify/` and `.agents/` files are present, ensures `.gitignore` contains `.agents/agents/*.local.md`, idempotently merges the `speckit.orchestrate` hook into `.specify/extensions.yml`, removes any obsolete upstream `.specify/scripts/` directory, updates `.specify/integrations/{speckit,agy,speckit-bootstrap}.manifest.json` with current SHA-256 digests, and prompts to run `/speckit-constitution` if `.specify/memory/{constitution,coding-standards,logging-standards}.md` are not yet ratified.
  - **Cross-Repo Install / Upgrade Mode (`/speckit-bootstrap <target-repo> [--upgrade] [--source=<source-repo>] [--force]`)**: Synchronizes managed files between the source bundle and `<target-repo>`, updating unmodified managed files whose on-disk SHA-256 digest matches `.specify/integrations/speckit-bootstrap.manifest.json`, skipping and warning on locally modified managed files (unless `--force` is passed), and preserving all protected user state.
  - **Dry-Run / Check Mode (`--check` or `--dry-run`)**: Outputs the complete file-by-file classification table (`CREATE`, `UPGRADE`, `PRESERVE_USER_STATE`, `SKIP_DRIFTED`, `REMOVE_OBSOLETE`, `UNCHANGED`) without mutating any files on disk.
  - **Governance Initialization Mode (`--init-governance`)**: Directly invokes (or spawns a subagent to invoke) `.agents/skills/speckit-constitution/SKILL.md` against the target repository so `.specify/memory/{constitution,coding-standards,logging-standards}.md` are generated and merged in a single workflow.
- **FR-006**: Both the ultra-thin seeder scripts (`bootstrap-speckit.sh`, `bootstrap-speckit.ps1`) and the `/speckit-bootstrap` skill MUST enforce a strict **Protected User-State Boundary** that is never overwritten or deleted during install, `--upgrade`, or `--force`:
  1. `.specify/memory/constitution.md`, `.specify/memory/coding-standards.md`, and `.specify/memory/logging-standards.md` (ratified project governance documents)
  2. `.specify/templates/overrides/**` (project-local template overrides)
  3. `.specify/feature.json` and `specs/**` (active feature specifications, plans, tasks, and contracts)
  4. `.agents/agents/*.local.md` and any custom stage-specific agent overrides (`.agents/agents/speckit-<stage>.md` or `.local.md`) not part of the two canonical role profiles
  5. Unrelated skills in `.agents/skills/` outside the managed `speckit-*` skill set.
- **FR-007**: The `/speckit-bootstrap` skill (and the initial manifest seeded by the repository) MUST maintain deterministic, SHA-256 digest-verified installation manifests in `.specify/integrations/` (`speckit.manifest.json`, `agy.manifest.json`, and `speckit-bootstrap.manifest.json`) that record the bundle version, timestamp, and SHA-256 digest of every managed file.
- **FR-008**: `/speckit-bootstrap`, `bootstrap-speckit.sh`, and `bootstrap-speckit.ps1` MUST emit structured operational messages and a final **Bootstrap Execution Summary** conforming to `.specify/memory/logging-standards.md` (`INFO` for lifecycle milestones, `WARN` for boundary rejections or skipped existing/drifted files, `CRITICAL` for broken internal invariants) reporting target path, mode, counts of files created, updated, unchanged, preserved, and skipped, and recommended next steps (`/speckit-constitution`, `/speckit-specify`, `/speckit-orchestrate`).
- **FR-009**: In compliance with Constitutional Principle III (*Static Verification & No Automated Tests*), all Phase 4 deliverables MUST be verified through static syntax and structure analysis, `--check` dry-run validation, and manifest SHA-256 digest verification, with zero automated test suites (`tests/`) or test tasks generated.

### Key Entities

- **Bootstrapper Skill (`speckit-bootstrap`)**: The intelligent agent skill in `.agents/skills/speckit-bootstrap/SKILL.md` that performs agent-native verification, manifest-gated non-destructive upgrades, `.gitignore` and `extensions.yml` merging, legacy `.specify/scripts/` cleanup, and optional `/speckit-constitution` governance initialization without requiring shell scripts.
- **Ultra-Thin Terminal Seed Scripts (`bootstrap-speckit.sh` & `bootstrap-speckit.ps1`)**: Minimal, cross-platform Bash and PowerShell file-copy seeders at the repository root that copy `.specify/` and `.agents/` into `<target-repo>` (respecting protected user state and optional `--force`/`-Force`) so the developer can launch their AI agent and run `/speckit-bootstrap`.
- **Base Governance Preset (`.specify/presets/base-governance/`)**: The Spec Kit preset package containing `preset.yml` and `templates/{constitution-template,coding-standards-template,logging-standards-template}.md`, registered in `.specify/presets/.registry` at Priority 2 (below project-local `.specify/templates/overrides/` and above core `.specify/templates/`).
- **Subagent Orchestrator Extension (`.specify/extensions/speckit-orchestrator/`)**: The Spec Kit extension package containing `extension.yml` and hook metadata registered in `.specify/extensions/.registry` and `.specify/extensions.yml`.
- **Bootstrap Installation Manifest (`.specify/integrations/speckit-bootstrap.manifest.json`)**: The JSON state record tracking bundle version, timestamps, and per-file SHA-256 checksums used by `/speckit-bootstrap` to distinguish unmodified managed files from locally customized files during `--upgrade`.
- **Protected User-State Set**: The explicit allowlist of project-owned paths (`.specify/memory/*.md`, `.specify/templates/overrides/**`, `.specify/feature.json`, `specs/**`, `.agents/agents/*.local.md`) guaranteed never to be clobbered by seeder or skill operations.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% of Spec Kit workflow skills (`specify`, `clarify`, `plan`, `tasks`, `checklist`, `analyze`, `implement`, `converge`, `constitution`, `orchestrate`, `bootstrap`) execute using native agent file and directory operations with 0 references to `.specify/scripts/bash/`, and `.specify/scripts/` is completely removed from the repository.
- **SC-002**: A maintainer on Linux, macOS, or Windows can seed a brand-new or existing repository using `./bootstrap-speckit.sh <target-repo>`, `pwsh ./bootstrap-speckit.ps1 <target-repo>`, or `/speckit-bootstrap <target-repo>` in a single command with 0 manual file copy steps.
- **SC-003**: Running `/speckit-bootstrap --upgrade` (or running the `.sh`/`.ps1` seeders against an already-initialized repo) preserves 100% of ratified governance files in `.specify/memory/`, 100% of local template overrides in `.specify/templates/overrides/`, 100% of `.agents/agents/*.local.md` overrides, and 100% of locally modified managed files (unless `--force` / `-Force` is explicitly passed).
- **SC-004**: Running `bootstrap-speckit.sh <target-repo>`, `bootstrap-speckit.ps1 <target-repo>`, or `/speckit-bootstrap` consecutively against an up-to-date target repository is 100% idempotent, reporting 0 created and 0 modified files on repeat execution.
- **SC-005**: Both `bootstrap-speckit.sh` and `bootstrap-speckit.ps1` remain lightweight, single-file seeders (under 150 lines each) with zero external package dependencies, delegating all structured configuration merging, drift analysis, and governance initialization to `.agents/skills/speckit-bootstrap/SKILL.md`.

## Assumptions

- **Skill-First Architecture with Ultra-Thin Cross-Platform Seeders**: All workflow and lifecycle intelligence—including feature state resolution, 4-tier template resolution, prerequisite verification, manifest-based upgrade drift detection, YAML hook merging, and constitutional merge—resides in pure Markdown skills under `.agents/skills/speckit-*/SKILL.md` with zero dependency on `.specify/scripts/bash/`. The root `bootstrap-speckit.sh` and `bootstrap-speckit.ps1` scripts are kept intentionally minimal: they only copy the `.specify/` and `.agents/` bundle into a target repository (skipping existing files unless `--force` / `-Force` is passed and never touching protected user state) so the agent has the skills loaded.
- **Preset + Core Template Synchronization**: Installing the governance templates into `.specify/presets/base-governance/templates/` (with `preset.yml` and `.specify/presets/.registry`) and keeping `.specify/templates/{constitution-template,coding-standards-template,logging-standards-template}.md` populated ensures that every skill resolving the 4-tier hierarchy (`overrides` → `presets` → `extensions` → `core`) discovers the exact same base governance templates while always yielding Priority 1 to `.specify/templates/overrides/`.
- **Checksum-Gated Non-Destructive Upgrades in `/speckit-bootstrap`**: Recording SHA-256 digests of all managed files in `.specify/integrations/speckit-bootstrap.manifest.json` (and updating `speckit.manifest.json` / `agy.manifest.json`) enables `/speckit-bootstrap --upgrade` to detect whether a file in `<target-repo>` was locally modified before updating it.
- **Agent-Driven Constitutional Merge Handoff**: When `/speckit-bootstrap` runs with `--init-governance` (or when the user accepts the post-bootstrap prompt), the agent directly executes `/speckit-constitution` to inspect the target repository and ratify `.specify/memory/{constitution,coding-standards,logging-standards}.md`.
